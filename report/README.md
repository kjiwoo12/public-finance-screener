# 검토조서

검토 결과를 **감사인이 쓰던 칸**에 담아 한 파일로 낸다.

```bash
python -m report                       # docs/workpaper.html
python -m report --json out/w.json     # 조서 내용을 JSON 으로도
```

의존성 없음. **자바스크립트도 쓰지 않는다** — 드릴다운은 `<details>` 만으로 만든다.
외부 스크립트·스타일·폰트를 하나도 참조하지 않으므로 첨부해서 보내도, 5년 뒤에 열어도
같은 문서다. 조서는 보존 대상이고, CDN 은 보존 대상이 아니다.

## 왜 별도 계층인가

조서의 **내용**은 `screen/` 이 만든다. 여기서는 그 내용을 한 글자도 바꾸지 않고
**읽는 순서만** 정한다.

렌더러가 요약하거나 보태기 시작하면 **화면에 보이는 것과 코드가 계산한 것이
갈라진다.** 그때부터 "이렇게 검토했다"는 말에 근거가 없다. 그래서 `render.py` 는
`screen` 도 `benchmark` 도 import 하지 않고 파일도 열지 않는다. 테스트가 확인한다.

## 칸의 순서

| 칸 | 무엇을 방어하는가 |
|---|---|
| 1 모집단 | 무엇을 다 봤다고 말하는가 |
| 2 적용 절차 | 어떤 눈으로 봤는가, 임계값은 어디서 왔는가 |
| 3 제외 | 올리지 않은 것과 그 이유 |
| 4 발견사항 | 올린 것 |
| 5 말할 수 없는 것 | 이 조서가 확인해 주지 않는 것 |

**제외가 발견사항보다 앞이다.** 발견사항을 먼저 놓으면 읽는 사람은 거기서 멈춘다.
그런데 감사 대상 선정에서 정작 방어해야 하는 것은 *"그럼 저기는 왜 안 봤나"* 쪽이다.
올린 16건보다 안 올린 1,604건이 이 도구가 하는 일에 가깝다.

## 모집단을 맞추는 칸이 결함 하나를 찾아냈다

1번 칸은 원본 파일 행수에서 살펴본 연도쌍까지 수가 줄어드는 자리를 전부 적는다.
그걸 처음 적어 보고 알았다.

```
원본 CSV 행        2,052
색인된 기관-연도    2,047      <- 5건이 사라진다
```

전부 `고성군상수도`다. 강원 고성군과 경남 고성군이 이름이 같은데 이 데이터셋에는
시도 열이 없다. `Table` 의 색인이 `(기관명, 연도)` 를 키로 쓰므로 **한쪽이 다른
쪽을 덮는다.** 덮인 쪽은 발견사항에도 제외 내역에도 없다 — 검토된 적이 없다.

수를 맞춰 보기 전까지 아무도 몰랐다. 조서가 하는 일이 이것이고, 그래서 이 사실을
고쳐서 감추지 않고 1번 칸에 경고로 띄운다.

## 감추지 않는다

조서에서 **빈칸은 "검토하지 않았음"과 "검토했으나 해당 없음"을 구별해 주지 못한다.**
비어 있는 항목은 공백으로 두지 않고 그 사실을 문장으로 적는다.

| 상태 | 화면에 나가는 문장 |
|---|---|
| 색인에서 빠진 행이 있음 | "이 행들은 발견사항에도 제외 내역에도 나타나지 않는다. 검토된 적이 없다는 뜻이다" |
| `excluded == {}` | "제외 기록이 없다. 임계값 아래로 걸러진 항목과 검토 후 제외한 항목을 이 조서로는 구별할 수 없다" |
| `findings == []` | "발견사항이 없다. 임계값에 걸린 건이 없었다는 뜻이고, 3번의 제외 내역이 무엇을 봤는지 말해 준다" |
| `open_questions == []` | "이 데이터로 답할 수 없는 것을 적지 않으면 질문이 아니라 판정이 된다" |
| `thresholds == []` | "이 절차는 임계값을 밝히지 않았다. 어떤 기준으로 걸렀는지 이 조서로는 알 수 없다" |

5번 칸은 이 도구가 채점된 적이 없다는 것과 **정밀도를 애초에 잴 수 없다**는 것을
조서 안에 적는다. 밖에 적어 두면 조서만 받은 사람은 확인된 도구로 읽는다.

## 작성일시를 넣지 않는다

조서에는 작성일이 들어가는 것이 보통이다. 넣지 않는 이유는 렌더된 조서를 저장소에
커밋하기 때문이다. 실행 시각을 찍으면 같은 자료에서 매번 다른 바이트가 나오고,
그러면 diff 가 무엇이 바뀌었는지 말해 주지 못한다. 대신 **자료의 회계연도 범위**를
적는다. 조서가 무엇을 근거로 만들어졌는지는 그쪽이 더 정확히 말해 준다.

테스트가 날짜 모양 문자열이 새어 들어왔는지 본다.

## 인쇄를 전제한다

조서는 출력되어 파일철에 들어간다. `@media print` 에서 배경·테두리를 걷어내고
카드가 페이지 사이에서 잘리지 않게 조판한다.

## 검증

```
python -m unittest tests.test_report      # 17개
```

| 묶음 | 검증 |
|---|---|
| `TestSelfContained` | 외부 참조 0, 태그 주입 이스케이프, **두 번 렌더하면 같은 바이트**, 실행 시각 없음 |
| `TestNothingIsAdded` | 렌더러가 `screen`·`benchmark`·파일을 건드리지 않음, 발견 원문이 그대로, 임계값이 규칙에서 옴 |
| `TestNothingIsHidden` | **모집단 대사가 맞음**, 사라진 행이 이름까지 화면에 나옴, 빈 칸이 문장으로 설명됨, 제외가 발견사항보다 앞 |
| `TestDrilldownReachesSource` | 원본 CSV 의 키와 값이 실제로 렌더링됨, `<details>` 기본 닫힘 |

## 한계

- **화면을 눈으로 확인하지 못했다.** 구조·문자열·계산된 스타일까지는 확인했지만
  스크린샷 도구가 응답하지 않아 조판을 사람 눈으로 본 적이 없다.
- 단일 문서다. 관점이 늘어 발견사항이 수백 건이 되면 목차와 페이징이 필요하다.
- 위험등급별 필터가 없다. 자바스크립트를 쓰지 않기로 한 대가다.
- 조서 서식은 이 저장소가 정한 것이고, **감사원이나 특정 회계법인의 실제 양식이
  아니다.** 칸 이름이 같아도 그 조직의 서식과 맞는지는 확인된 바 없다.
